# plan-close

작업이 완료된 plan 문서의 내용을 spec 본문에 흡수하고, work 문서를 삭제하여 하나의 작업을 종료하는 흐름.

## 인자

```
/plan-close                        ← 컨텍스트에서 plan 문서 탐색
/plan-close docs/work/auth-flow.md ← 명시 지정
```

인자가 없으면 `docs/work/` 안에서 모든 단계가 완료된 문서를 찾는다.

## 흐름

### 1. 종료 조건 확인

1. plan 문서의 **작업 단계** 표에서 모든 행이 `완료` 또는 `건너뜀`인지 확인한다.
2. **종료 게이트**의 조건을 하나씩 점검한다.
3. 미충족 조건이 있으면 사용자에게 알리고, `/plan-run`으로 돌아갈지 그대로 닫을지 확인한다.

### 2. spec 반영

plan 문서의 내용을 spec 문서에 흡수한다.

**대상 spec 판단:**
1. plan 문서의 **참조 절**에 링크된 spec 문서가 있으면 해당 spec에 머지한다.
2. 기존 spec의 **"다루는 범위 / 다루지 않는 범위"** 표를 확인하여, 이 작업 내용이 기존 spec의 범위에 속하는지 판단한다.
3. 어느 spec에도 속하지 않는 새 도메인이면 `docs/template/spec.md` 골격으로 새 spec을 생성한다.
4. 여러 spec에 걸치면 각각에 해당 부분을 나누어 반영한다.

**반영 내용:**
- 작업 범위 상세의 설계 결정 → spec 본문 해당 절
- 다루지 않는 항목 중 이관 처리된 것 → 대상 spec의 범위 표
- 새로 생긴 PENDING 마커 → `docs/pending.md` 항목 확인

### 3. 정합성 검사

1. `pnpm docs:generate --write`로 참조 절·목차·미확정 사항 절을 갱신한다.
2. `pnpm docs:check`로 전체 정합성을 확인한다.
3. 지적이 있으면 수정한다.

### 4. work 문서 삭제

1. 사용자에게 삭제 대상 파일을 보여주고 확인을 받는다.
2. 승인하면 `docs/work/<name>.md`를 삭제한다.
3. 삭제 후 `pnpm docs:check`를 한 번 더 실행하여 깨진 링크가 없는지 확인한다.

## 판단 기준

- spec 반영 전에 반드시 사용자 확인을 받는다. 자동으로 머지하지 않는다.
- 새 spec 생성 시 사용자에게 파일 이름과 위치를 확인한다.
- work 문서 삭제는 항상 사용자 승인 후에만 실행한다.

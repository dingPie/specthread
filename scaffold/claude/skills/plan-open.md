# plan-open

새 작업의 계획 문서를 `docs/work/`에 생성하고, 검수를 거쳐 확정하는 흐름.

## 인자

```
/plan-open                        ← 새 작업 문서 생성
/plan-open docs/work/auth-flow.md ← 기존 초안 이어서 작업
```

인자가 없으면 작업 이름을 물어본 뒤 `docs/work/<name>.md`를 새로 만든다.
인자가 있으면 해당 파일을 읽고 이어서 진행한다.

## 흐름

### 1. 초안 작성

1. 사용자와 대화하며 각 절을 채운다:
   - **목표 + 종료 게이트**: 검증 가능한 조건으로. "잘 정리됐다"는 게이트가 아니다.
   - **작업 단계**: 순서와 의존 관계.
   - **작업 범위 상세**: 코드 시그니처, 데이터 모양, 예시 등 구체적 내용.
   - **영향 파일**: 실제로 손댈 파일. 이 절을 못 채우면 계획이 덜 선 것이다.
   - **다루지 않는 항목**: 후보에서 빠진 것을 처리·이유와 함께 적는다.
   - **검증 기준**: 자동(테스트, 빌드)과 사용자(기능 동작, 시각 검수)를 나눈다.
   - **예상 산출물**: 코드 외에 갱신할 문서가 있으면 함께 적는다.
2. 모호한 부분은 `PENDING::<종류>::<slug>` 마커를 남기고 넘어간다.
3. 결정 사항은 별도 절이 아니라 **해당 절 본문에** 반영하고, 변경 이력에 기록한다.

### 2. 검수

1. 초안을 사용자에게 제시한다.
2. `npx specthread check`를 실행해서 형식 문제를 확인한다.
3. 사용자 피드백을 반영하여 수정한다.

### 3. 확정

1. 사용자가 승인하면 `npx specthread gen --write`로 참조 절·목차를 채운다.
2. 최종 `npx specthread check`로 정합성을 확인한다.
3. 문서가 확정되었음을 안내하고, 다음 단계(`/plan-run`)를 안내한다.

## 판단 기준

- 영향 파일 절이 비어 있으면 확정하지 않는다.
- 종료 게이트가 검증 불가능하면 다시 쓴다.
- 미확정 마커는 있어도 확정 가능하다 - 작업을 멈추지 않기 위한 장치다.

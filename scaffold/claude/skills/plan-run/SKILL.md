# plan-run

확정된 계획 문서의 작업 단계를 실행하고, 확인 필요 항목을 기록하며, 검토를 거쳐 보완하는 흐름.

## 인자

```
/plan-run                        ← 컨텍스트에서 plan 문서 탐색
/plan-run docs/work/auth-flow.md ← 명시 지정
```

인자가 없으면 `docs/work/` 안에서 현재 작업과 관련된 문서를 찾는다. 판단할 수 없으면 묻는다.

## 흐름

### 1. 작업 파악

1. plan 문서의 **작업 단계** 표를 읽는다.
2. 상태가 `대기`인 첫 번째 단계를 확인한다.
3. 해당 단계의 **작업 범위 상세** 절을 읽고 무엇을 할지 파악한다.

### 2. 실행

1. 작업 범위 상세에 따라 구현한다.
2. 진행 중 확인이 필요한 것을 발견하면 확인 필요 절에 행을 추가하고 사용자에게 묻는다.
   - 다음 단계를 막는 유형이면 다음 단계로 가기 전에 확정하거나 보류한다.
   - 보류로 정하면 `specthread/pending.md` 에 등록하고, 다른 작업에서 바꿀 위치에 `PENDING::<종류>::<slug>` 마커를 남긴다.
3. 단계가 끝나면 plan 문서의 작업 단계 표에서 해당 행의 상태를 `완료`로 갱신한다.
4. 남은 확인 필요 항목이 있으면 제목과 개수를 사용자에게 알린다.

### 3. 검토

1. `npx specthread check`를 실행한다.
2. 검증 기준(자동 + 사용자)을 확인한다.
3. 사용자에게 검토 결과를 제시한다.

### 4. 보완

1. 사용자 피드백에 따라 수정한다.
2. plan 문서의 변경 이력에 기록한다.
3. 다음 단계가 있으면 1번으로 돌아간다.
4. 모든 단계가 완료되면 `/plan-close`를 안내한다.

## 판단 기준

- plan 문서의 작업 단계 표가 유일한 진행 상태 원천이다. 별도 상태 표기를 만들지 않는다.
- 결정 사항은 plan 문서 해당 절 본문에 반영하고, 변경 이력에 남긴다.
- 예상 산출물에 적힌 spec 반영은 plan-close 에서 진행한다. 작업 중에는 spec 을 고치지 않는다.
